## 문제: 답변이 생성되는 동안 진행 상태를 확인하기

사내 문서에 답하는 Private LLM 서비스에서 VPN 안내 기능을 점검하고 있습니다. 지금은 답변이 완성될 때까지 화면이 그대로여서 사용자가 요청이 접수됐는지 알기 어렵습니다. 운영 담당자도 답변이 비어 있을 때 모델 호출이 실패한 것인지, 출력 처리가 잘못된 것인지 구분하기 어렵습니다.

주어진 VPN 안내 문서로 실제 모델 답변을 한 번 생성하세요. 답변 조각은 도착하는 대로 이어서 보여 주고, 같은 실행의 단계 이름·모델 상태·출력 이벤트 수·경과 시간·토큰 사용량을 로컬에 기록합니다. 완성된 답변은 문자열로 반환해 이후 저장 기능에서도 사용할 수 있어야 합니다.

예제 문서는 가상의 사내 안내입니다. 이 실습에서는 OpenAI API로 답변을 생성하며, 별도의 사내 모델 서버나 외부 관측 서비스 계정은 필요하지 않습니다.

### 제공되는 입력과 코드

| 항목 | 내용 |
| --- | --- |
| `CONTEXT` | VPN 연결 실패 시 프로그램 재실행, 계속 실패하면 IT 지원팀 문의 |
| `QUESTION` | VPN 연결이 계속 실패하면 어떻게 해야 하는지 묻는 질문 |
| 체인 | 문서와 질문을 받는 Prompt → ChatOpenAI → StrOutputParser |
| `LocalTrace` | LangChain Callback을 실제로 받는 클래스. 시작·오류 처리와 단계 이름 기록은 제공 |
| `stream_usage=True` | 스트리밍 종료 시 모델이 제공하는 사용량 정보도 요청하는 설정 |

`LocalTrace`는 요청마다 새로 만듭니다. 답변 본문과 API 키를 관측 필드에 저장하지 않으며, 수집한 값은 현재 Python 실행의 메모리에만 남습니다. 단계 목록은 각 단계가 시작됐다는 기록입니다. 모든 단계의 시작·종료를 가진 전체 실행 트리를 저장하는 기능은 아닙니다.

### 완성할 부분

**TODO 1 — 내용이 있는 출력 이벤트 세기**

`on_llm_new_token(token, **kwargs)`은 모델이 출력 이벤트를 보낼 때 호출됩니다. `token`이 문자열이면서 빈 문자열이 아닐 때만 `self.text_events`를 1 증가시키세요. 반환값은 없습니다. 답변을 여기서 다시 출력하지 않습니다. 마지막 사용량 이벤트처럼 본문이 없는 이벤트도 올 수 있습니다.

**TODO 2 — 모델 완료 결과 기록하기**

`on_llm_end(response, **kwargs)`의 `response`는 모델의 완료 결과입니다. 다음 네 값을 처리하세요.

- 현재 `time.perf_counter()`에서 `self.started_at`을 뺀 값을 밀리초로 바꿔 `self.elapsed_ms`에 저장합니다.
- `self.status`를 `"completed"`로 바꿉니다.
- 이 실습의 단일 응답은 `response.generations[0][0].message`에서 읽습니다.
- 메시지의 `usage_metadata`를 `self.usage`에 보관합니다. 속성이 없으면 `None`으로 둡니다. `getattr(객체, 속성명, 기본값)`을 사용할 수 있습니다.

문자 수나 이벤트 수로 토큰 사용량을 계산하지 마세요. 화면 표시 코드는 `None`을 `제공되지 않음`으로 바꿔 줍니다.

**TODO 3 — 한 번의 스트리밍에서 출력과 수집 함께 하기**

`stream_answer(chain, payload, trace)`는 체인, 문서·질문 딕셔너리, 관측 객체를 받아 전체 답변 `str`을 반환합니다.

1. 조각을 모을 리스트를 만듭니다.
2. `chain.stream()`을 한 번 호출합니다. 실행 설정에는 `callbacks` 목록에 `trace`, `run_name`에 `"VPN 안내"`를 넣습니다.
3. 도착한 문자열 조각을 순서대로 보관하고 `print(..., end="", flush=True)`로 출력합니다.
4. 반복문이 끝나면 줄을 바꾸고 조각을 빈 구분자로 합칩니다.
5. 공백을 제외한 내용이 없으면 `ValueError`를 발생시키고, 내용이 있으면 합친 문자열을 반환합니다.

최종 체인이 `StrOutputParser`로 끝나므로 반복문에서는 문자열을 받습니다. 기록을 얻기 위해 `invoke()`를 추가로 호출할 필요가 없습니다.

### 완료 조건

모델 답변에는 VPN 프로그램을 다시 실행하고, 그 뒤에도 연결이 실패하면 IT 지원팀에 문의하라는 절차가 담겨야 합니다. 코드에서는 전체 문자열이 비어 있지 않은지, Callback의 완료 상태가 기록됐는지 확인합니다. 조치의 순서와 문의 대상이 맞는지는 실제 출력도 읽어 확인하세요.

모델 호출이 실패하면 제공된 오류 Callback이 예외 종류를 기록하고 오류가 호출자에게 전달됩니다. 이미 화면에 나온 일부 조각만으로 정상 완료를 판단하지 않습니다.

## 문제 · 공지 원문과 두 가지 분석 결과를 함께 반환하기

사내 Private LLM 문서 도우미에 새 공지를 등록하려고 합니다. 운영 담당자는 목록에서 읽을 한 문장 요약과 공지를 찾을 때 쓸 검색어가 필요합니다. 나중에 결과를 확인할 수 있도록 공지 원문과 문서 ID도 그대로 남겨야 합니다.

주어진 가상 공지 한 건을 정리한 뒤, 요약과 검색어를 각각 생성하는 체인을 완성하세요. 두 분석은 같은 공지를 읽습니다. 검색어를 만들기 위해 요약 결과를 기다릴 필요는 없습니다.

### 주어진 입력

`NOTICE`는 다음 두 필드를 가진 딕셔너리입니다.

| 필드 | 의미 |
| --- | --- |
| `document_id` | 결과가 어느 공지에서 나왔는지 구분하는 ID. 값은 `notice-014`입니다. |
| `text` | 담당자 검토, 승인 문서 등록, 변경 문서 교체에 관한 공지 원문. 앞뒤에 공백이 있습니다. |

모델에 보낼 두 Prompt와 실행 확인 코드는 제공되어 있습니다. 요약 Prompt와 검색어 Prompt는 모두 `{clean_text}`라는 변수를 사용합니다.

### 만들어야 할 결과

최종 결과에는 원래 두 필드와 새 필드 세 개가 함께 있어야 합니다.

| 결과 필드 | 요구사항 |
| --- | --- |
| `document_id`, `text` | 입력값을 그대로 유지합니다. `text`의 앞뒤 공백도 보관합니다. |
| `clean_text` | `text`의 앞뒤 공백만 제거한 문자열입니다. |
| `text_length` | `clean_text`를 Python의 `len()`으로 센 값입니다. |
| `analysis` | `summary`와 `keywords`라는 키를 가진 딕셔너리입니다. 각 값은 모델이 생성한 문자열입니다. |

요약에는 담당자 검토, 승인된 문서 등록, 변경 문서 교체가 담겨야 합니다. 검색어는 공지의 내용을 나타내는 짧은 표현 세 개를 쉼표로 구분합니다. 표현 자체는 모델에 따라 달라질 수 있습니다.

## 문제 상황

Private LLM 서비스의 첫 화면에 직원이 바로 읽을 수 있는 안내 카드를 붙이려고 합니다. 가상의 VPN 안내문을 입력하면 모델은 짧은 요약과 조치 목록을 만들고, 프로그램은 이를 번호가 있는 카드로 표시해야 합니다.

기존 카드 데이터에는 요약을 담는 `summary`와 조치 두 개를 쉼표로 구분한 문자열 `steps`가 있습니다. 지금은 이 형식을 유지하면서 화면에 표시할 때만 `steps`를 Python 리스트로 바꾸려고 합니다. 모델을 여러 번 호출하지 않고, 응답 한 개를 세 Parser로 처리하세요.

## 주어진 입력과 만들 결과

`DOCUMENT`는 “VPN 연결이 끊기면 프로그램을 다시 실행하고, 계속 실패하면 IT지원팀에 문의한다”는 실습용 안내문입니다. `AUDIENCE`는 `"처음 출근한 직원"`입니다. 실제 사내 문서를 준비할 필요가 없습니다.

모델에는 다음 형식을 요청합니다.

| 필드 | 필요한 내용 |
| --- | --- |
| `summary` | 안내문의 핵심을 담은 한 문장입니다. 비어 있지 않은 문자열이어야 합니다. |
| `steps` | 수행할 조치 두 개를 순서대로 쉼표로 나눈 문자열입니다. 각 조치 자체에는 쉼표를 넣지 않습니다. |

`steps`는 이 입력 형식에서 JSON 배열이 아니라 문자열입니다. 변환 후 화면에는 요약 한 줄과 `1. ...`, `2. ...` 두 줄을 표시합니다. JSON 필드 이름은 같아야 하지만 문구는 모델마다 달라질 수 있습니다.

## 구현할 부분

### TODO 1. 문자열 입력을 역할별 메시지에 넣기

`make_messages(document, audience)` 안의 두 템플릿은 제공되어 있습니다.

- `text_template`에 안내문과 대상 독자를 넣어 `user_text` 문자열을 만드세요.
- `chat_template`에는 `user_text`와 두 Parser의 형식 안내를 전달합니다. `json_format`은 `JsonOutputParser`, `list_format`은 `CommaSeparatedListOutputParser`의 `get_format_instructions()` 결과입니다.
- 완성한 `user_text`와 역할별 메시지 목록을 이 순서로 반환하세요.

고정 원칙은 `system`, 이번 안내문과 독자는 `human`에 들어갑니다. 목록 형식 안내는 전체 응답이 아니라 JSON 안의 `steps` 문자열에 적용된다는 문장이 `RULES`에 준비되어 있습니다. 템플릿에 넣을 변수 이름을 확인하세요.

### TODO 2. 응답 한 개를 문자열·딕셔너리·리스트로 변환하기

`read_card(message)`는 모델이 반환한 `AIMessage`를 받습니다.

1. `StrOutputParser`로 본문 문자열을 꺼냅니다.
2. `JsonOutputParser`로 그 문자열을 변환합니다.
3. 결과가 딕셔너리이고 `summary`, `steps` 두 키가 있는지 검사합니다. 이어서 두 값 모두 비어 있지 않은 문자열인지 확인합니다. 조건에 맞지 않으면 `ValueError`를 발생시키세요.
4. `steps` 문자열에 목록 Parser를 적용하고, 원문 문자열·변환한 딕셔너리·조치 리스트를 이 순서로 반환합니다.

딕셔너리 여부와 키를 확인하기 전에 `card["steps"]`부터 읽으면 형식이 잘못된 응답에서 다른 오류가 먼저 발생할 수 있습니다. 타입·키 확인을 먼저 하세요. 이번 검사는 필요한 두 키와 문자열 값을 확인하며, 추가 키가 있는지는 검사하지 않습니다.

### TODO 3. 화면용 카드 만들기

`render_card(card, steps)`에서 조치가 정확히 두 개이고 각 조치가 공백만 있는 문자열이 아닌지 확인하세요. 맞지 않으면 `ValueError`를 발생시킵니다. 정상일 때는 요약을 첫 줄에 두고, 조치에 1부터 번호를 붙여 줄바꿈으로 합친 문자열을 반환합니다.
